插件和商业计划变化；"—"表示该能力不是该方案的核心内置体验，"外部工具"表示通常
需要命令行、插件或额外配置。对第三方产品的标注以公开产品定位为依据，建议在选型前
按目标平台和具体版本复核。

## 定位差异

- **rclone** 是命令行优先的同步与迁移瑞士军刀：后端覆盖最广、同步策略最全、脚本生态
  最成熟。它没有图形工作台；如果你的一切操作都在终端里完成，rclone 仍是第一选择。
- **WinSCP** 是 Windows 上成熟的 SFTP/FTP 图形客户端，传输队列和目录保持同步很实用；
  对象存储支持以 S3 为主，宿主集成与策略门禁不在其范围。
- **传统文件管理器** 面向本地盘；远端协议要么依赖系统挂载（SMB），要么需要外部工具，
  缺少传输队列和协议级安全门禁。
- **DBX Files** 把"多协议浏览 + 传输任务 + 归档 + 受控策略"收进 DBX 宿主工作台：
  凭据由宿主统一管理，同一能力通过 MCP 工具暴露给自动化客户端。它不追求替代
  rclone 的命令行生态，而是让图形化与自动化共享同一套连接与权限边界。

## DBX 插件家族中的位置

| 插件 | 主要对象 | 适合任务 |
| --- | --- | --- |
| DBX Files | 文件系统与对象存储 | 文件浏览、上传下载、归档和跨存储整理 |
| DBX SSH 终端 | SSH 主机、终端、SFTP、远程运维 | 登录服务器、执行命令、浏览与传输文件 |
| DBX LDAP | LDAP 目录 | 查询、统计、编辑目录条目 |
| DBX Kafka | Kafka 集群 | Topic、消息、消费组和 Schema 运维 |

Files 不重复实现 SSH 终端、LDAP 或 Kafka 的专用协议；它专注于"对文件系统与对象
存储的统一文件操作"，并通过 DBX 宿主能力复用连接、凭据和工作台桥接。SSH 场景下的
文件传输可按需选择 DBX SSH 终端（SFTP）或本插件的 sftp/sftp-native 连接。

## 如何选择

- 一切操作在终端里完成、需要脚本生态和最多后端：选 rclone。
- Windows 上主力是 SFTP/FTP 且需要成熟图形客户端：选 WinSCP。
- 只管理本地盘：系统自带的文件管理器就够。
- 已在 DBX 中使用宿主连接、MCP 或插件工作台，或需要把多协议文件运维与自动化放进
  同一套连接与权限边界：选 DBX Files。
